Task 11 — Step 1 of 3: Clinic Foundation + Patient Records + Appointments + Prescriptions

CONTEXT:
- Tasks 1-10 complete. AppShule serves Education + Microfinance sectors
- Task 11 introduces CLINIC/PHARMACY/DRUG SHOP sector
- This step builds the foundation: patient records, appointments, 
  doctor/nurse workflows, and prescription management
- Task 11 Step 2 will add Pharmacy + Product Scanner
- Task 11 Step 3 will add Dashboard + Insurance + Reports

GOAL OF STEP 1:
- New "Clinic" institution type (extends Institution Management from Task 9)
- New roles: Clinic Admin, Doctor, Nurse, Receptionist, Pharmacist, Patient
- Patient registration and records
- Appointment scheduling and check-in
- Visit documentation (symptoms, diagnosis, vitals)
- Prescription management

PART A: NEW FIRESTORE COLLECTIONS
═══════════════════════════════════════════════════════════════

Create these collections:

1. clinic_patients
   Fields:
   - patientId (Firebase uid or auto)
   - patientNumber (auto-generated: CLN-{year}-{sequence})
   - firstName, lastName
   - dateOfBirth
   - gender (Male/Female/Other)
   - phone (required)
   - email (optional)
   - nationalId
   - address
   - emergencyContactName
   - emergencyContactPhone
   - bloodType (A+, A-, B+, B-, AB+, AB-, O+, O-)
   - allergies (array of strings)
   - chronicConditions (array of strings)
   - insuranceProvider (optional)
   - insuranceNumber (optional)
   - photoUrl (Firebase Storage URL)
   - institutionId (which clinic)
   - branchId (optional)
   - createdBy (uid)
   - createdAt
   - status (active/inactive/deceased)

2. clinic_appointments
   Fields:
   - appointmentId (auto)
   - patientId (reference)
   - patientName (denormalized)
   - doctorId (uid of doctor)
   - doctorName
   - appointmentDate (date)
   - appointmentTime (time slot)
   - appointmentType (General Checkup / Dental / Follow-up / 
     Emergency / Lab Test / Consultation / Vaccination)
   - reason (text)
   - notes (text)
   - status (scheduled/checked_in/in_progress/completed/
     cancelled/no_show)
   - institutionId
   - branchId
   - createdBy (uid)
   - createdAt
   - updatedAt
   - checkedInAt (timestamp)
   - completedAt (timestamp)

3. clinic_visits
   Fields:
   - visitId (auto)
   - patientId
   - patientNumber
   - appointmentId (optional — may be walk-in)
   - doctorId
   - doctorName
   - visitDate (date)
   - visitTime (time)
   - visitType (Appointment / Walk-in / Emergency)
   - symptoms (text — patient's complaint)
   - diagnosis (text — doctor's diagnosis)
   - treatmentPlan (text)
   - doctorNotes (text)
   - vitals:
     - weight (kg)
     - height (cm)
     - bpSystolic (mmHg)
     - bpDiastolic (mmHg)
     - temperature (°C)
     - heartRate (bpm)
     - oxygenSaturation (%)
     - respiratoryRate (breaths/min)
   - followUpDate (date, optional)
   - followUpNotes (text)
   - status (in_progress/completed/referred)
   - institutionId
   - branchId
   - createdBy
   - createdAt
   - completedAt

4. clinic_prescriptions
   Fields:
   - prescriptionId (auto)
   - visitId (reference)
   - patientId
   - patientName
   - doctorId
   - doctorName
   - medicationName (string)
   - dosage (string — e.g. "500mg")
   - frequency (string — e.g. "Twice daily")
   - duration (string — e.g. "7 days")
   - quantity (number)
   - instructions (text — e.g. "Take after meals")
   - status (pending/dispensed/partially_dispensed/cancelled)
   - dispensedBy (uid — Pharmacist)
   - dispensedAt (timestamp)
   - notes (text)
   - institutionId
   - branchId
   - createdAt

5. clinic_services
   Fields:
   - serviceId (auto)
   - name (string — e.g. "General Consultation")
   - description (text)
   - price (number, UGX)
   - category (Consultation/Lab/Pharmacy/Dental/Surgery/Imaging/Other)
   - durationMinutes (number)
   - isActive (boolean, default true)
   - institutionId
   - sortOrder
   - createdAt

6. clinic_branches
   Fields:
   - branchId (auto)
   - name (string — e.g. "Main Branch Kampala")
   - location (text)
   - phone
   - managerId (uid)
   - managerName
   - institutionId
   - isActive (boolean)
   - createdAt

PART D: NEW USER ROLES
═══════════════════════════════════════════════════════════════

Add 6 new roles to the User Management system:

1. Clinic Admin (full access to one clinic)
   - Manages staff, services, patients
   - Views all reports and analytics

2. Doctor
   - Sees patient records for their appointments
   - Records visits, diagnoses, prescriptions
   - Cannot manage staff or billing

3. Nurse
   - Checks in patients, records vitals
   - Assists doctor
   - Cannot write prescriptions

4. Receptionist
   - Registers patients
   - Schedules appointments
   - Checks in patients
   - Cannot view medical details

5. Pharmacist
   - Dispenses prescriptions
   - Manages pharmacy inventory
   - Records pharmacy sales
   - Cannot edit medical records

6. Patient (borrower-like role)
   - Views their own appointments
   - Views their own prescriptions
   - Cannot modify anything

Update the User Management role dropdown to include these 6 roles.
When creating a user with Clinic role, institution dropdown shows 
only Clinic institutions.
