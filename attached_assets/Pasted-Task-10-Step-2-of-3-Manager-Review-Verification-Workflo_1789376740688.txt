Task 10 — Step 2 of 3: Manager Review + Verification Workflow + Document Storage

CONTEXT:
- Step 1 built: MFI foundation, Customer registration, Collateral capture, 
  Auto-scoring engine (0-100)
- Now we build the manager review workflow, verification process, and 
  document management that MFIs need for UMRA compliance

GOAL OF STEP 2:
Enable Loan Managers to review collateral scores, approve/reject loans,
schedule field visits, request valuer reports, and store all documents
securely. This creates the full audit trail UMRA requires.

YOUTUBE / ToS NOTE: Not applicable.

═══════════════════════════════════════════════════════════════
PART A: NEW FIRESTORE COLLECTIONS
═══════════════════════════════════════════════════════════════

Create these collections:

1. mfi_collateral_verification
   Fields:
   - verificationId (auto)
   - collateralId (reference to mfi_collateral)
   - activity (Desk Review / Field Visit / Valuer Report / Legal Check)
   - assignedTo (user uid — Loan Officer or Valuer)
   - assignedToName (string)
   - scheduledDate (date)
   - completedDate (date)
   - notes (text)
   - status (pending / in_progress / completed / cancelled)
   - attachments (array of Firebase Storage URLs)
   - createdBy (uid)
   - createdAt (timestamp)

2. mfi_collateral_decisions
   Fields:
   - decisionId (auto)
   - collateralId (reference)
   - decision (approved / rejected / topup_requested)
   - managerComments (text)
   - requiredTopupAmount (number — if topup_requested)
   - requiredTopupType (string — what kind of additional collateral needed)
   - decidedBy (manager uid)
   - decidedByName (string)
   - decidedAt (timestamp)
   - status (final / under_appeal)

3. mfi_valuers (registry of certified valuers)
   Fields:
   - valuerId (auto)
   - fullName (string)
   - company (string)
   - licenseNumber (string)
   - phone (string)
   - email (string)
   - specialization (Land / Vehicles / Business Assets / General)
   - institutionId (which MFI they work with)
   - isActive (boolean, default true)
   - createdAt (timestamp)

4. mfi_legal_officers (registry of lawyers)
   Fields:
   - officerId (auto)
   - fullName
   - lawFirm
   - licenseNumber
   - phone
   - email
   - institutionId
   - isActive
   - createdAt

PART F: VERIFICATION WORKFLOW
═══════════════════════════════════════════════════════════════

When manager clicks [+ Schedule Verification Activity]:

Modal (id="scheduleVerificationModal"):

Activity Type (dropdown):
1. Desk Review (1 day)
2. Field Visit (3-5 days)
3. Valuer Report (7 days — required if asset > UGX 20M)
4. Legal Check (3 days — required for Land)

Fields:
- Activity Type (dropdown)
- Assign To (dropdown):
  * Loan Officer
  * Registered Valuer (if type == Valuer Report)
  * Registered Legal Officer (if type == Legal Check)
- Scheduled Date (date picker)
- Notes (textarea)

System logic:
- If collateral value > UGX 20M: Valuer Report is REQUIRED
- If collateral type == Land: Legal Check is REQUIRED
- Show which activities are auto-added based on rules

On save:
- Create mfi_collateral_verification doc
- Notify assigned person
- Update collateral.verificationStage

When assigned person completes activity:
- Tap on notification → opens activity detail
- Upload attachments (photos, documents)
- Add completion notes
- Mark as [✅ Complete]
- Notifies manager
