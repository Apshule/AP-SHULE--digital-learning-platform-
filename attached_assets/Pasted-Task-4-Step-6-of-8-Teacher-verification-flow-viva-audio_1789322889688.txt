GOAL:
Teacher reviews each student's milestone uploads, verifies authenticity, 
and either approves or rejects. Teacher must:
1. See a list of pending projects assigned to their subject/class
2. View milestone photos + timestamps + QR code
3. Tick "I observed this student working on it"
4. Record a 30-second viva audio (student explains project)
5. Approve or reject with a comment

When approved:
- milestone status → "approved"
- Create a ca_records entry (for Task 1's CA export)

PART D: VIVA AUDIO RECORDING
═══════════════════════════════════════════════════════════════

Add audio recording using MediaRecorder API:

1. When teacher taps [🔴 Record]:
   - Request microphone permission
   - Start MediaRecorder
   - Show timer counting up: "0:00 / 0:30"
   - Auto-stop at 30 seconds
   - Show visual feedback (pulsing red dot)
   - Button becomes [⏹ Stop] to stop early

2. When recording stops:
   - Convert recording blob to file
   - Show preview: [▶️ Play recording] to verify
   - Add [🔄 Re-record] button
   - Keep the blob in memory

3. When teacher taps [✅ Approve]:
   - Upload viva audio to Firebase Storage:
     * Path: projects/{schoolId}/{learnerId}/{projectId}/viva_{milestoneNumber}.webm
   - Save download URL to project doc:
     * viva_audio_path = URL
     * viva_audio_uploadedAt = serverTimestamp()

Fallback:
- If browser doesn't support MediaRecorder:
  - Show message: "Audio recording not supported in this browser"
  - Allow approval without viva (log a warning)
- If teacher denies microphone permission:
  - Show message and allow "Approve without viva" with a warning

═══════════════════════════════════════════════════════════════
PART E: APPROVE FLOW
═══════════════════════════════════════════════════════════════

When teacher clicks [✅ Approve]:

Validation:
1. Check teacher_observed_tick is checked (the ☐ box must be ☑)
   - If not checked, show error: "Please confirm you observed the student"
2. Check viva audio was recorded OR "Approve without viva" was chosen
   - If neither, show error: "Please record viva audio first"

On successful validation:
1. Update project doc:
   - teacher_observed_tick = true
   - viva_audio_path = (uploaded URL)
   - viva_audio_uploadedAt = serverTimestamp()
   - verifiedBy = currentUser.uid
   - verifiedAt = serverTimestamp()
   - milestone_{N}_status = "approved"
   - milestone_{N}_comment = (teacher's comment)
   - milestone_{N}_approvedAt = serverTimestamp()
   - updatedAt = serverTimestamp()

2. Create a ca_records entry (Task 1 collection):
   {
     learnerId: project.learnerId,
     schoolId: project.schoolId,
     subject: project.subject,
     competency: "Project Work — " + project.title,
     evidence1: "Milestone " + N + " photo uploaded",
     evidence2: "Teacher observed: yes",
     evidence3: "Viva audio recorded",
     finalLevel: "Meets",  // default, can be changed later
     term: project.term,
     teacherId: currentUser.uid,
     syncedAt: serverTimestamp(),
     createdAt: serverTimestamp()
   }

3. Send notification to student:
   {
     type: 'project_approved',
     title: '✅ Milestone {N} approved!',
     body: '"{projectTitle}" — teacher approved your {milestoneName}.',
     targetUserId: project.learnerId,
     timestamp: serverTimestamp(),
     author: currentUser.name
   }

4. Close the review modal
5. Refresh the pending list
6. Show toast: "✅ Milestone approved"

Special case — if this was milestone 2 or 3:
- Milestone 1 was already approved, so student can now upload Milestone 2
- After Milestone 2 approved → Milestone 3 unlocked
- After Milestone 3 (final) approved → project is fully complete

If milestone N was the FINAL milestone:
- Set project status = "completed" (add new field)
- Notify school admin: "{studentName}'s project '{title}' is complete."

PART F: REJECT FLOW
═══════════════════════════════════════════════════════════════

When teacher clicks [❌ Reject]:

1. Show a prompt asking for the reason (required, min 20 chars)
   - Use a small modal with a textarea
   - Examples shown as placeholder: "Photo unclear, please re-upload"

2. On confirm:
   - Update project doc:
     * milestone_{N}_status = "rejected"
     * milestone_{N}_comment = (reason)
     * milestone_{N}_rejectedAt = serverTimestamp()
     * verifiedBy = currentUser.uid
     * updatedAt = serverTimestamp()
   - Send notification to student:
     {
       type: 'project_rejected',
       title: '❌ Milestone {N} needs work',
       body: '"{projectTitle}" — {reason}. Please re-upload.',
       targetUserId: project.learnerId,
       timestamp: serverTimestamp(),
       author: currentUser.name
     }
   - Close the modal
   - Refresh list
   - Show toast: "Milestone rejected — student notified"

3. Student can re-upload the milestone (this is allowed after reject)
