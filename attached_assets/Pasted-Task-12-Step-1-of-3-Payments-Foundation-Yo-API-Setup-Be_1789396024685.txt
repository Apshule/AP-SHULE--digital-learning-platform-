Task 12 — Step 1 of 3: Payments Foundation + Yo! API Setup + Beneficiary Management + Collection Flow

CONTEXT:
- Tasks 1-11 complete. AppShule serves Education + MFI + Clinic sectors
- Task 12 introduces AUTOMATED PAYMENTS via Yo! Payments
- This task handles COLLECTION (clients paying institutions) and 
  DISBURSEMENT (institutions receiving funds)
- AppShule acts as the master aggregator — its own Yo! account 
  receives payments, then auto-disburses to institutions

CRITICAL NOTES:
- Yo! Payments uses XML, NOT JSON
- Use Asynchronous mode (NonBlocking=TRUE) for all collections
- Verify all webhooks with RSA signature
- Do NOT download YouTube videos (ToS)
- Do NOT expose API credentials in frontend code

GOAL OF STEP 1:
- Yo! API configuration panel (Super Admin only)
- Institution beneficiary management
- Client payment initiation flow
- IPN (Instant Payment Notification) webhook handler
- Full audit trail of all transactions

On [💳 Pay Now]:
1. Validate amount > 0 and <= balance
2. Create payment_transactions doc with:
   - status = "pending"
   - reference = auto-generated
   - all relevant fields
3. Call backend API (Firebase Function) that:
   a. Reads Yo! credentials from secure storage
   b. Builds XML request:
      <?xml version="1.0" encoding="UTF-8"?>
      <AutoCreate>
        <Request>
          <APIUsername>{YO_API_USERNAME}</APIUsername>
          <APIpassword>{YO_API_PASSWORD}</APIPassword>
          <Method>acdepositfunds</Method>
          <NonBlocking>TRUE</NonBlocking>
          <Amount>{amount}</Amount>
          <Account>{clientPhone}</Account>
          <Narrative>{billReference} payment</Narrative>
          <ExternalReference>{reference}</ExternalReference>
          <InstantNotificationUrl>{IPN_URL}</InstantNotificationUrl>
          <FailureNotificationUrl>{FAILURE_URL}</FailureNotificationUrl>
        </Request>
      </AutoCreate>
   c. Sends request to Yo! API
   d. Returns response to client
4. Client sees:
   "📱 Check your phone for PIN prompt.
    Amount: UGX 185,850
    Reference: {reference}
    [Waiting for confirmation...]"
5. Client enters PIN on their phone
6. Yo! sends IPN webhook to AppShule (see Part E)
7. Client's UI updates to "✅ Payment Confirmed" when IPN received

If failed (timeout, cancel, insufficient funds):
- Show "❌ Payment failed. Try again?"
- Log failure
- Keep transaction with status = "failed"

PART E: IPN WEBHOOK HANDLER (CRITICAL)
═══════════════════════════════════════════════════════════════

The IPN webhook is where Yo! calls AppShule back when payment succeeds.

Setup:
1. Create Firebase Cloud Function (or Replit server endpoint):
   POST /api/webhooks/yo/ipn
2. Same for failure:
   POST /api/webhooks/yo/failure

IPN HANDLER LOGIC (pseudocode):
1. Receive POST from Yo! with form-urlencoded data:
   - date_time
   - amount
   - narrative
   - network_ref
   - external_ref
   - msisdn
   - payer_names
   - payer_email
   - signature

2. Verify signature:
   - Decode base64 signature
   - Verify using Yo!'s public key + SHA1
   - If invalid → log + return 401

3. Check for duplicate:
   - Query yo_webhook_logs WHERE network_ref + msisdn matches
   - If duplicate → return 200 OK (skip processing)

4. Find transaction:
   - Query payment_transactions WHERE reference == external_ref
   - If not found → log + return 200 OK

5. Update transaction:
   - status = "completed"
   - yoTransactionId = reference
   - yoNetworkRef = network_ref
   - yoMsisdn = msisdn
   - yoWebhookData = full payload
   - paymentDate = serverTimestamp()

6. Process balance:
   - Update bill/loan in respective sector:
     * clinic_billing: amount_paid += amount, 
       balance_remaining -= amount
     * microfinance_loans: same pattern
     * school_fees: same pattern
   - Compute new status: Fully Paid / Partially Paid / Overpaid
   - If overpaid: create credit_note (see Task 12 Step 2)

7. Trigger auto-disbursement (if enabled):
   - Call backend function disburseToInstitution()
   - Creates payment_disbursements doc

8. Send notifications:
   - Client: "✅ Payment confirmed. Balance: UGX X"
   - Institution: "New payment received"
   - Super Admin: "Transaction processed"

9. Respond to Yo! with HTTP 200 OK
   - Optionally include SMS text in response body:
     narrative=Thank+you%2C+your+payment+is+confirmed.

FAILURE HANDLER (similar):
1. Verify signature
2. Find transaction by failed_transaction_reference
3. Update status = "failed"
4. Notify client: "❌ Payment failed"
5. Return 200 OK

Webhook logs:
- Log ALL incoming webhooks (success or fail)
- Store raw payload for audit
- Log verification result

PART J: SECURITY
═══════════════════════════════════════════════════════════════

Critical security measures:

1. API credentials:
   - Stored in Firebase Functions env variables OR
   - Encrypted Firestore doc accessible only to super admin
   - NEVER sent to client
   - Rotate keys periodically

2. Webhook verification:
   - Verify every IPN with Yo!'s public key
   - Reject unverified webhooks
   - Log all attempts

3. Idempotency:
   - Check network_ref + msisdn for duplicates
   - Never process same webhook twice
   - Store processed webhook IDs

4. Rate limiting:
   - Limit payment attempts per user (5 per hour)
   - Show "Too many attempts. Wait 1 hour."
   - Log suspicious patterns

5. Audit log:
   - Every action logged with user, timestamp, IP
   - Immutable — no deletion allowed
